# 音乐软件适配测试

每个音乐软件都按同一份清单测，结果记在文末的表里。测之前先在设置的“音乐来源”里选“自动”，测到需要手动选择来源的项时再切换。

## 准备

- 软件已登录，能正常播放。准备两首歌：一首中文（有翻译或逐字歌词更好）、一首英文。
- Glance 的音乐面板（屏幕边缘）和全屏音乐都要用到。

## 清单

### A. 识别
1. 歌名、歌手与软件里显示的一致。
2. 封面与软件里显示的一致。
3. 面板上的播放器名称正确。
4. 自动模式下能跟随到这个软件，在“音乐来源”里手动选它时也能跟随。

### B. 控制（在 Glance 的面板上操作，看软件里的变化）
1. 播放、暂停：软件随之切换，Glance 上的按钮状态在一秒内跟上。
2. 下一首、上一首：软件换歌，Glance 的歌名、封面、歌词随之更换。
3. 在软件里直接暂停、切歌：Glance 在一秒内跟上。

### C. 进度
1. 播放中的时间与软件一致（误差一秒以内），暂停后停在同一处。
2. 拖动 Glance 的进度条：软件跳到对应位置，歌词随之跳到对应的行。
3. 软件不提供进度时，Glance 显示“播放器未提供播放进度”，不显示错误的时间。

### D. 歌词
1. 能找到歌词（或说明找不到的原因）。
2. 当前行与软件里正在唱的行一致，换行时机误差在半秒以内。
3. 有翻译时显示翻译，有逐字时间时逐字高亮。
4. 在歌词上滚动滚轮翻到另一行，点它旁边的时间（▷ 0:56），软件跳到那一行。

### E. 状态
1. 换歌后封面、歌词、进度在两秒内全部换成新歌的。
2. 隐藏 Glance 的所有窗口一段时间，暂停或换歌后再打开，显示的是当前状态。
3. 关掉软件：Glance 显示没有在播放，不卡在最后一首。

### F. 全屏音乐与律动
1. 全屏音乐里的歌词、进度、控制按钮都正常。
2. 律动条随音乐跳动，暂停后静止。
3. 音量滑块改变系统音量，松手后不跳回。

## 问题记录

网易云音乐（2026-10-17，InfLink-rs 插件，网易云 3.x）：

- 开头的“作词、作曲、编曲、制作人”几行，网易云显示、Glance 原先略去：现在照网易云给出的显示（c5d8679）。
- E3：关掉网易云后三秒内，小组件显示“当前没有正在播放的歌曲”。重新打开网易云，又跟上了当前的歌。
- E2（Glance 全部隐藏时暂停、换歌）未测：桌面上的小组件一直显示着，Glance 没有全部隐藏的时候。

QQ 音乐（2026-10-17，QQ 音乐 2222 版，D:\App\QQMusic）：

- 系统媒体控制里有歌名、歌手、专辑、进度和时长，能播放、暂停、切歌，但不允许外部改进度（IsPlaybackPositionEnabled 为假）。
- 《牡丹亭 - 浅影阿》网易云和 LRCLIB 都没有歌词，Glance 显示“没有找到这首歌的歌词”，QQ 音乐自己有。现在歌词也向 QQ 音乐要，在 QQ 音乐里播放的歌优先用它自己的歌词（73de7d6）。
- QQ 音乐不让改进度，Glance 原先仍在翻到的歌词行旁显示“▷ 时间”，全屏的进度条也能拖、方向键也能快进快退，按了没有反应。现在都随播放器是否允许（f464ce7），面板的进度条原本就是这样。
- 播放器名称显示为“QQ音乐 听我想听”：这是 QQ 音乐程序文件自己的描述，Windows 的音量合成器里也是这个名字，不改。
- 换歌后歌名、封面、进度立即更新，歌词要等网上查到，约两三秒。
- E3：关掉 QQ 音乐，它的会话立即从系统里消失，Glance 不会停在它的最后一首。

Spotify（2026-10-17，免费账号）：

- 歌名、歌手、专辑、封面、进度都有，能拖动进度，翻到的歌词行点时间也能跳过去。
- 英文歌的歌词来自网易云，有逐字时间和中文翻译，全屏里按单词整体排列。
- E3：Glance 正显示 Spotify 时关掉它，三秒内 Glance 转到网易云（暂停中的那首）。
- 设置“音乐来源”里它的名字原先显示为“Spotify8FileV”：它的程序文件把描述的长度按字节写，Glance 多读了后面的内容。现在读到描述结尾为止（e065bbc）。

Apple Music（2026-10-17，微软商店版）：

- 登录时报“连接到苹果服务器出错”。这台电脑缺 Apple Root CA，苹果登录服务器 gsa.apple.com 的证书链验证不了。装上 Apple Root CA 后证书能验证通过，但登录仍然出错，暂不测。

浏览器（2026-10-17，Edge，YouTube Music）：

- 网易云网页版在这里因版权地区限制不能播放，改用 YouTube Music。
- 浏览器把视频也说成音乐，自动模式按设计不跟随浏览器，在“音乐来源”里选 Microsoft Edge 后跟随。工作台的“正在播放”一行本来就跟随它。
- 设置里的“音乐来源”原先一行放不下所有播放器，“自动”被挤出卡片左边看不到。现在放不下的选项换到下一行（13ee2bd）。
- YouTube Music 中文界面把歌手写成中文译名（Coldplay 写作“酷玩乐队”），Glance 原先按歌手名对不上，找不到歌词。现在会查网易云对这个译名的歌手，再按原名匹配（4b7c4f0）。
- YouTube Music 放的是 MV 版本时，长度和专辑版不同（The Scientist 4:25 对 5:09），歌词时间对不上，Glance 不取专辑版歌词，显示“没有找到这首歌的歌词”，这是对的。
- 暂停、播放、下一首、拖动进度都正常，歌词逐行对得上，全屏正常。
- E3：关掉 YouTube Music 标签页，Edge 的媒体会话换成另一个标签页里暂停的视频，Glance 随即显示它。

本地音乐（2026-10-17，Windows 媒体播放器，测试用的歌曲文件，测完已删除）：

- 歌名、歌手、专辑都有，歌词从同名 LRC 文件读出，逐行对得上，律动条正常。
- 媒体播放器不把歌曲文件里的封面交给系统，Glance 原先没有封面。现在从音乐库里对应的文件读封面：先读标签里的图片（ID3 的 APIC、FLAC 和 Ogg 的图片、MP4 的 covr），再用 Windows 给这个文件的缩略图（fb0a407）。ID3v2.4 标签里的封面 Windows 读不出来，Glance 自己读得出。
- 拖动进度后，媒体播放器报给系统的位置要过一会儿才更新，Glance 按拖到的位置往下走，歌词也对。
- 播放中关掉媒体播放器，Glance 转到暂停中的网易云，却显示在歌的末尾：把媒体播放器关掉前的“正在播放”当成了网易云刚暂停，把网易云半小时前报的位置一路推算到了结尾。现在只对同一个播放器的同一首歌这样推算（6d49dbf）。
