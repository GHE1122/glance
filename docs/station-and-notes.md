# 中转站与便签：设计说明

状态：主人已确认方向（2026-10-18），文末记下了定下的事，剩下的细节在动手时决定。

这两个组件都是之前定下的组件之一（监控、歌词、中转站、便签、快捷 App、控制中心）。它们和已有组件共用同一套外壳：
- 可以放到屏幕边缘呼出。
- 可以从面板上拖出来，成为桌面小组件。
- 可以和别的组件合并。

## 一、中转站

### 它做什么

中转站是一个临时放东西的架子。在两个窗口、两个程序或者电脑和手机之间搬东西时，先把东西放在这里，回头再从这里拖出去用。典型的场景有：
- 从资源管理器拖几个文件进来，切到聊天软件，再把它们拖出去发送。
- 在网页上看到一张图、一段话、一个链接，先丢进来，过一会儿整理。
- 手机拍的照片发到电脑上，在中转站里取。

它不是文件管理器，也不是网盘。东西放进来是为了很快再拿出去。

### 放进去的方式

1. **拖进来**：把文件、文件夹、图片、选中的文字、网页链接拖到中转站上。
   - 拖着东西碰到中转站所在的屏幕边缘时，面板会自己弹出来，不用先把它打开。这一点最重要，Mac 上 Dropover、Yoink 这类工具好用就在于此。
   - 做法是在那段边缘放一条看不见的窄条窗口，接收系统的拖放事件。东西拖到它上面，就把面板弹出来。
2. **粘贴**：中转站打开时按 Ctrl+V，把剪贴板里的文件、图片或文字放进来。
3. **从手机发过来**：在“手机互联”里打开中转站这一项后，手机可以把照片和文件发进中转站。手机只能碰到中转站里的东西，碰不到电脑上的其他文件夹，这是之前定下的规则。

### 存的方式

已定（主人同意）：
- **拖进来的文件和文件夹**：只记它在哪里，不复制。占用空间为零，也不会出现同一个文件的两份。原文件被移走或删掉后，中转站里这一项显示“原文件已不在”。
- **本来没有文件的东西**：粘贴的图片和文字、从网页拖来的图片、手机发来的照片，中转站在自己的文件夹里存一份（`%LOCALAPPDATA%\Glance\Station\`）。
- 每一项都可以单独选“保留一份副本”，这样原文件之后被删也不受影响。设置里另有“总是保留副本”。

### 每一项长什么样

- **文件**：图标，图片和视频显示缩略图，下面是文件名，再小一点的字是大小和放进来的时间。
- **一次拖进来的多个文件**：叠成一摞，显示“5 个文件”，可以展开，也可以整摞拖出去。
- **文字**：显示前两三行。
- **链接**：显示网址的域名和路径。这里不联网去抓网页标题，因为那样会把你放进来的每个链接都发给对方网站。

### 拿出来和其他操作

- **拖出去**：拖到任何程序里都行，文件拖出去是文件，文字拖出去是文字，图片两种都给，由接收方选。可以多选后一起拖出去。
- **打开**：双击打开，文件夹在资源管理器里打开，链接在浏览器里打开。
- **预览**：选中后按空格，在中转站上方弹出一个大一点的预览，可以看图片和文字，再按空格关掉。
- **右键菜单**：复制、在资源管理器中显示、保留一份副本、固定、移除。
- **拖出去以后这一项要不要留着**：默认留着。可以在设置里改成拖出去后自动移除。

### 能放多久

已定（主人同意）：
- 没有固定的项目，放进来 7 天后自动移除。
- 固定的项目一直留着。
- 中转站自己存的副本总共不超过 2 GB，超过时先移除最早的未固定项目。
- 7 天和 2 GB 都可以在设置里改。

### 剪贴板历史

已定（主人）：默认打开，第一期就做。它是中转站里单独的一栏“最近复制”，复制过的文字、图片和文件都会出现在这里，可以拖出去或重新复制。

因为它会记录复制过的所有东西，必须有两道保护：
- 自动跳过密码管理器和浏览器标记为“不要记录”的内容（Windows 为此定义了专门的剪贴板格式，例如 `ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory` 为 0）。
- 可以一键暂停，托盘菜单和中转站里都有。暂停时中转站上有明显标记。

“最近复制”也按 7 天过期，固定后留下。

### 放在哪里、多大

- **边缘面板**：在“布局”页里拖到某条边上即可。默认放在哪条边，主人让我动手时决定（顶部也可以）。
- **桌面小组件**：和音乐一样按尺寸切换版式。
  - 窄条：一排最近的几项。
  - 卡片：网格。
  - 竖长：列表。
- 打开时顶部一行：标题、件数、“全部清空”。
- 下面是项目。拖东西进来时，整个面板变成一个高亮的放置区。

## 二、便签

### 它做什么

便签用来随手记下想法、待办和要记住的东西。核心要求是快：从呼出到可以打字，不超过半秒，不用先点“新建”。

### 呼出和输入

- **从边缘呼出**：面板一打开，光标就在最近那一条便签的末尾，直接打字。
- **快捷键呼出**：可以设成“新建一条”。
- **自动保存**：停止打字半秒后保存，没有保存按钮。
- **标题**：每条便签的第一行就是它的标题，不用另起。

### 内容格式

已定（主人）：支持 Markdown，边写边显示效果，像 Typora、Obsidian 的实时预览那样：
- 文件里存的是标准 Markdown，用别的编辑器打开也正常。
- 编辑时，标题直接变大，**粗体**、*斜体*、列表、引用、行内代码和代码块、链接都实时显示效果。
- Markdown 的符号（`#`、`**`、`>` 这些）淡淡地显示在原处，不打断输入，光标离开那一行时可以进一步收起。
- **待办**：`- [ ]` 显示成一个可以点的方框，点了变成 `- [x]` 并划掉。
- **网址**：自动变成可点的链接。
- **图片**：第一期不在便签里显示。把图片（包括中转站里的）拖进便签时，复制一份到便签文件夹的“附件”目录，便签里放一个指向它的链接（见第六节第 9 条）。第二期再考虑在便签里直接显示图片。

做法：用 RichEdit 引擎负责输入，Glance 自己解析 Markdown（Rust 的 pulldown-cmark），按解析结果给文字套上字号、粗细、颜色等格式。两者不冲突。

### 很多条便签怎么管理

- 面板左侧（或上方，窄的时候）是便签列表，按最近修改排序，右侧是正在编辑的那一条。
- 支持搜索标题和正文。
- 不做文件夹和标签，第一期保持简单。

### 样子

主人看中了一个开源的玻璃卡片设计（alexko0421/glass-card，复刻自设计师 Sam 的 Event Stack Shifting），用它作为便签的视觉方向：
- 每条便签是一张彩色、半透明的毛玻璃卡片，几种柔和的颜色（蓝、绿、黄、橙、粉、紫、灰、白）可选，新建时轮换。
- 卡片叠在一起时，后面卡片的颜色透过前面的玻璃显出来。Glance 的毛玻璃本来就取窗口后面的画面，所以这一点是现成的。
- 卡片左上角一个小图标，下面一行小字（修改时间），再下面是标题，右上角是“…”菜单。
- 只借鉴视觉，不用它的代码（那是 SwiftUI 写的）。

### 贴在桌面上

- 任何一条便签都可以“贴到桌面”，变成一张单独的玻璃卡片小组件。
- 它可以直接编辑。
- 贴在桌面上的便签就画成它的编辑页的样子：顶部是颜色圆点和修改时间，正文按编辑框的字体、字号和位置排版（Markdown 同样显示），底部是字数和文件名。点开编辑时，编辑页正好盖在原处，大小相同，下面的小组件在编辑期间隐藏，所以编辑前后看上去几乎没有变化。
- 从编辑页拖出来，或在编辑页的菜单里选“贴到桌面”，小组件和那一页一样大。从面板上的卡片直接拖出来，默认 360 × 320。贴在桌面上的便签只显示这一条，不翻页。
- 待办清单贴在桌面上，最实用。

### 存在哪里

已定（主人同意）：
- 每条便签存成一个普通的 .md 文本文件，默认在 `文档\Glance 便签\`。
- 好处是没有 Glance 也能打开，用户自己的同步盘（OneDrive、坚果云、Syncthing）同步这个文件夹就能多台电脑共用。
- 设置里可以改到别的文件夹。
- 文件被别的程序改了，Glance 会察觉并处理，做法见第六节第 3 条。原则是两边的内容都不丢。

### 和其他组件的联动

- **插入当前读数**：在便签里插入当前的硬件读数（CPU 温度、显卡占用等）。之前的规划里提过，第二期做。
- **手机互联**：打开便签这一项后，手机上可以看和改便签，两边同步，第二期做。
- **提醒**：给待办设一个时间，到时用 Windows 通知提醒，第二期再考虑。

## 三、技术上要先验证的事

1. **中文输入法**：这是便签最大的技术风险。
   - Glance 的界面是自己画的，没有现成的文本框。自己从零实现输入法支持（候选框位置、组合输入、选择、撤销、复制粘贴）工作量很大，也容易出错。
   - 我的打算是用 Windows 自带的 RichEdit 文本引擎，以“无窗口”方式嵌进 Glance 自己画的界面里，让它负责输入法、选择、撤销和剪贴板，画面仍由 Glance 绘制，保持毛玻璃等外观。
   - 这需要先做一个小试验，确认中文输入法的候选框位置正确、和 Glance 的绘制方式兼容、能按 Markdown 解析结果给文字套格式，再正式做。
2. **拖放**：Glance 的界面进程已经不是管理员权限，和资源管理器、浏览器之间互相拖放都没有问题。被系统拦下的是从 Glance 拖到“以管理员身份运行”的程序里（低权限往高权限），这种情况很少，界面上提示原因，并提供“复制到剪贴板”作为替代。传输的内容绝不经过以管理员权限运行的传感器进程。
3. **拖到边缘时弹出面板**：用上面说的窄条放置窗口实现，需要试验它在全屏程序、多屏、屏幕接缝处的表现。
4. **缩略图**：用 Windows 资源管理器同一套缩略图接口，图片、视频、PDF 都能出缩略图。它会加载第三方的缩略图插件，但运行在普通权限的界面进程里，风险可以接受。

## 四、分期

**第一期**
- 中转站：拖进、粘贴、拖出、打开、预览、移除、固定、自动过期、拖到边缘弹出、边缘面板与小组件、剪贴板历史（默认打开）。
- 便签：先做输入法试验，通过后做列表、编辑、自动保存、Markdown 实时显示、待办、链接、搜索、玻璃卡片外观、贴到桌面、存为 .md。

**第二期**
- 中转站：和手机互传。
- 便签：手机同步、插入读数、提醒。

先做中转站，因为它不依赖输入法试验，可以马上开始。便签的输入法试验和中转站同时进行。

## 六、实现约定（2026-10-18，Codex 审查后补充）

方案交给 Codex 单独审查过一次。以下是审查指出、并且我核实后认为必须在动手前定下来的事，按重要程度排列。

1. **拖放和编辑需要单独的界面线程**。现在面板和小组件所在的线程按 MTA 方式初始化 COM，而系统的拖放（RegisterDragDrop、DoDragDrop）只能在 OLE 初始化过的 STA 线程上用。中转站和便签的窗口放在一个新的 STA 线程上，它有自己的消息循环，和现有绘制线程之间只传消息，不共享锁。
2. **便签要有“编辑模式”**。现在的组件窗口不抢焦点（点它时键盘输入仍留在原来的程序里），这对监控组件是对的，对便签不行。点进便签正文时窗口转为可获得焦点，离开后恢复原样。输入法试验必须在真正会移动、会缩放的面板和组件里做，覆盖移动中、缩放中、多屏不同缩放比例三种情况，Windows 10 和 11 各测一遍。RichEdit 的光标、点击位置和输入法候选框位置都要换算上编辑区的偏移、滚动和屏幕缩放。
3. **便签文件的冲突处理**。面板里和贴在桌面上的同一条便签共用一份内容。每次保存记下文件的修改时间和内容摘要。保存前先核对文件是否被别的程序改过：改过就不覆盖，而是把两份都留下，外部的那份另存为“（冲突副本）”，并在便签上提示。保存用“写临时文件再替换”的方式，中途断电也不会留下半个文件。收到文件变化的通知时，只有本地没有未保存的改动才直接重新读入，否则按冲突处理。
4. **拖进中转站只按“复制”方式接收**。只记位置时，如果告诉来源程序这次是“移动”，它会把原文件删掉，中转站里就只剩一个空引用。所以拖进来一律回复“复制”，拖出去也默认“复制”。真正要移动文件时，另做一个明确的“移动到…”操作。
5. **剪贴板记录按序号抓取**。系统的“剪贴板变了”通知不带内容，连续复制两次时，读到的可能都是第二次的内容。做法是每次读取都核对剪贴板序号，排除格式的检查和读取内容在同一次打开剪贴板时完成，读出的数据在关闭剪贴板前复制成自己的一份，暂停时丢弃还在排队的读取。连续很快的复制可能有中间的一次记不到，这一点在设置里写明。
6. **三个隐私格式各管各的**。
   - 带有 `ExcludeClipboardContentFromMonitorProcessing` 的内容：完全不记。
   - `CanIncludeInClipboardHistory` 为 0 的内容：不进“最近复制”。
   - `CanUploadToCloudClipboard` 为 0 的内容：可以记在本机，但这个标记要跟着这一项保存。重新复制它时，把标记一起放回剪贴板，以后和手机互传时也不传它。
7. **从浏览器、邮件里拖出的“虚拟文件”要当场存下来**。这类拖放没有真实路径，只给文件名和内容流，来源程序关掉后就再也拿不到。所以拖进来时立即把内容写成中转站自己的文件（名字由 Glance 生成，大小有上限，图片按安全的方式解码）。中转站自己存的文件被拖出去后，要等对方读完才允许清理。
8. **Markdown 格式不进撤销记录**。按解析结果给文字套格式只是“装饰”，要放在撤销记录之外，并且保持选区和正在输入的拼音不受影响。保存的永远是原始 Markdown 文本，不从显示效果反推。解析结果的位置要明确换算成 RichEdit 的位置（UTF-16，注意换行的表示）。输入法试验的通过条件里加一条：套过格式后保存出来的文字和输入的一字不差，并且中文和表情符号的输入、撤销、重做都正确。
9. **便签里的图片放在便签自己的文件夹里**。原计划是便签里放一个指向中转站的链接，但中转站的东西 7 天后会被自动移除，便签里就只剩一个失效的链接。改为：把中转站的图片拖进便签时，复制一份到便签文件夹下的“附件”目录，用相对路径引用。这样同步便签文件夹时，图片也一起同步。
10. **空间上限和固定项不冲突**。如果固定的项目已经占满 2 GB，新的东西放不进来时直接提示“空间已满”，请用户取消一些固定或在设置里调大上限。绝不自动删除固定的项目，也不悄悄丢掉刚放进来的东西。
11. **卡片之间互相透色需要另外实现**。现有的毛玻璃取的是窗口后面的桌面，取不到同一个面板里别的卡片。面板里叠放的卡片，由 Glance 自己把后面的卡片模糊后画在前面卡片的底下。贴在桌面上的卡片各是一个窗口，天然就能透出后面的卡片。

## 七、第六节第 1 条的落实方式（2026-10-18，动手时补充）

第六节第 1 条写的是“中转站和便签的窗口放在新的 STA 线程上”。照字面做，中转站就要有一套自己的窗口外壳，这和已经定下的“所有组件共用同一套外壳、可以和别的组件合并”冲突：合并后的小组件是一个窗口，不可能一半在面板线程、一半在另一个线程。

因此改为下面的做法，第 1 条要解决的问题（拖放必须在 OLE 初始化过的 STA 线程上进行）照样解决：
- 中转站和便签的界面仍由共用的外壳绘制，窗口仍归面板线程所有。
- 新的 STA 线程（`glance: station`）负责所有 OLE 的事：替外壳的窗口登记拖放目标，接收拖进来的东西；开始往外拖；读写剪贴板。系统把拖放事件交给登记它的线程，所以这些事件都在 STA 线程上发生。
- 两个线程之间只传消息：STA 线程告诉面板线程“有东西拖到了某处”“拖走了”，面板线程只负责画高亮；中转站里有什么，由 STA 线程发布一份只读的副本。
- 这个做法依赖两件需要先验证的事：一是在另一个线程上为窗口登记拖放目标是否被系统接受，二是从 STA 线程开始往外拖时，鼠标在面板线程的窗口里按下，拖动能否正常进行（必要时在拖动期间把两个线程的输入连在一起）。验证在虚拟机里做，验证不通过再回到第 1 条的字面做法，同时把合并组件的方式重新设计一遍。

验证结果（2026-10-18，Windows 11 虚拟机，两次结果一致）：
- 往外拖可以：在面板线程的窗口里按下，由 STA 线程开始拖动，拖动正常开始。
- 替另一个线程的窗口登记拖放目标不行：登记本身返回成功，但东西拖到那个窗口上时，系统把拖放交给窗口所属的线程处理，那个线程没有初始化 OLE，拖动就停在那里不动了。
- 另外看到：正在进行拖放时，发起拖动的线程持有鼠标捕获的窗口，类名是 `CLIPBRDWNDCLASS`。从外面可以据此认出“有人在拖东西”，和拖动窗口、拖选文字区分开。

因此接收拖放改为这样做：
- 中转站线程每隔约 0.1 秒看一次前台线程是否正在拖放（看它持有捕获的窗口类名）。
- 只在有人拖东西的这段时间里，中转站线程在每个显示着中转站的地方（面板里、小组件里，见 `station::run::shows_at`）和放着中转站的屏幕边缘，放上自己的透明接收窗口。这些窗口属于中转站线程，拖放能正常进行。
- 拖放结束后这些窗口立刻撤掉。平时屏幕边缘和组件上没有多余的窗口，不会挡住最大化窗口贴边的滚动条或标签页的点击，也不会挡住面板和小组件本身。
- 拖到放着中转站的屏幕边缘时，接收窗口告诉面板线程把中转站弹出来，然后东西放在弹出的中转站上。

## 八、工作台的整体做法（2026-10-18，主人看过可交互小样后确认）

小样：https://claude.ai/artifact/5NcuQoyRXpDzk9QJRzzFSd （第 11 版）。主人的原话是“外观方面主要还是依靠我们现有的外观，小样只是提供一个参考”。所以下面定的是有哪些东西、怎么操作，画法沿用三种皮肤现有的控件、字号、颜色和圆角，不照搬小样的样子。

### 工作台里有什么

工作台是一个组件组，里面有四块：时间（含正在播放）、中转站、便签、快捷 App。

- **时间**：已有，不变。
- **中转站**：顶部是三个标签“中转站 / 最近复制 / 最近文件”，标签上可以直接按住拖出（见下文）。
  - “中转站”标签有三种视图：卡片、列表、图片。三个标签放下后位置不够，所以视图用一个下拉按钮切换。
  - 每一块各自滚动，整个面板不滚动。
- **便签**：三种视图：叠放、小卡片、列表。标题栏有搜索和新建。
- **快捷 App**：
  - 在左右两侧边缘时，它是贴着屏幕边缘的一条竖栏。在顶部边缘时，它是放在三块下面的一行。
  - 竖栏底部是三个按钮：握把（整个面板拖出）、固定、设置。

### 旁边展开的那一页

预览中转站里的东西、编辑便签、添加程序，都在面板内侧旁边展开一页。从小组件里打开时，展开在那个小组件旁边，右侧放不下就放左侧。点别处或按 Esc 收起。

### 快捷 App

- **添加程序**：自己做一个选择页，不用系统的文件对话框。
  - 列出“开始”菜单里的全部程序（`shell:AppsFolder`，桌面程序和商店应用都在里面），带图标，按名字和拼音首字母搜索。
  - 找不到的，把 exe、快捷方式、文件夹或网址拖到竖栏或选择页上。
- **启动**：由界面进程启动，所以程序以用户身份运行，不会继承管理员权限。
- **其他操作**：竖栏里的图标拖动排序，右键可以打开所在位置或移除。

### 从面板拖出小组件

这是对“小组件只能从面板上撕下来”的细化：
- **拖出某一块**：按住某一块的标题或标签拖出面板，出来的只是这一块。时间块按住空白处，快捷 App 按住竖栏的空白处。
- **拖出整个面板**：按住竖栏底部的握把拖出，整个面板成为一个小组件。之前拉动整个面板撕下的做法保留。
- **拖出一条便签**：从面板或便签小组件里把一条便签拖出来，它就贴在桌面上。便签菜单里的“贴到桌面”效果相同。
- **面板里的内容不变**：小组件只是又一个显示同一份内容的地方，数据只有一份，面板里的东西不会因此减少。
- **同一条便签只开一个编辑框**：已经贴在桌面上的便签，在别处再点它，面板收起，桌面上那张闪一下并排到最前面，不再另开一个编辑框。删除便签时，桌面上那张一起去掉。
- **存的方式**：小组件的设置里记下它显示的是哪一块（`PanelLayout` 加一个“只显示某一块”的字段），或者贴的是哪一条便签。旧版本读到不认识的值时不显示这个小组件，不会显示成别的东西。

### 小组件按尺寸换版式

和音乐一样，按尺寸切换版式：
- **中转站**：窄条（一排缩略图，放不下的显示“+N”）、卡片、列表。
- **便签**：整组便签，或者矮的时候只显示一条。
- **快捷 App**：一排图标，拉高后变成带名字的网格。

### 最近文件

列出最近新出现在用户文件夹里的文件，不管它落在哪里：下载的、截的图、新保存的文档。

- **显示**：按今天、昨天、更早分组，可以按全部、下载、截图、文档、图片和视频筛选。
- **每一行的来源**：下载的文件读它的 `Zone.Identifier`，写“来自某网站”。其他文件写所在的文件夹。
- **操作和中转站一致**：单击复制，双击打开，拖出去是复制一份。右键菜单有打开、在资源管理器中显示、放入中转站、复制路径、不再列出这个文件夹。
- **在哪个进程里读**：在界面进程里，以用户的权限读，绝不经过管理员权限的传感器进程。`docs/architecture.md` 定过，服务告诉界面的东西只能用来显示，不能是要打开的路径。以用户的权限读，还有一个好处：用户打不开的文件本来就读不到，不用另外按权限过滤。
- **怎么读**：
  - 先试 NTFS 给普通用户的变更日志读取方式（`FSCTL_READ_UNPRIVILEGED_USN_JOURNAL`）。如果它给出文件名，就用它，因为它记得 Glance 没在运行时新增的文件。
  - 如果不给，就对每个固定磁盘的根目录用 `ReadDirectoryChangesW` 监视整棵目录树，新文件记进 Glance 自己的列表。
  - 先做一个小试验定下用哪种。
- **排除**：系统文件夹、程序文件夹、各程序的缓存和临时文件、`AppData`、`.git` 和构建产物这类文件夹默认不列出。用户可以再加要排除的文件夹，也可以在设置里关掉整个功能。

### 实现顺序

1. 中转站一块：三个标签、视图下拉、列表和图片视图，去掉暂停。
2. 最近文件：先做读取方式的小试验，再做功能。
3. 从面板拖出某一块和整个面板。
4. 快捷 App：竖栏、选择页、拖入、启动。
5. 旁边展开的那一页：先用于中转站的预览。
6. 便签：先做输入法试验，再做列表、编辑页、存 .md、贴到桌面。

每一步单独提交，自己在虚拟机里验证过再交给主人看。

### 第八节的补充（2026-10-18，Codex 单独审查设计后）

1. **普通权限读变更日志拿不到文件名**。Codex 实测：以普通权限打开 `C:\` 根目录（`GENERIC_READ` 加 `FILE_FLAG_BACKUP_SEMANTICS`）可以读，819 条记录的文件名长度都是 0。打开 `\.\C:` 要么被拒，要么读不了日志。
   - 记录里仍有文件编号，所以小试验改为验证另一条路：对“新建”记录用 `OpenFileById` 按编号打开文件，再用 `GetFinalPathNameByHandleW` 取路径。用户打不开的文件自然打不开，等于按权限过滤。
   - 这条路通，就用它，因为它记得 Glance 没运行时新增的文件。不通，就用目录监视。
   - 用目录监视时要补三件事：启动时和缓冲区溢出（返回 0 字节或 `ERROR_NOTIFY_ENUM_DIR`）后重新扫描一遍对账，在后台线程做读写，网络盘和可移动盘默认不监视。
2. **旧版本兼容**：serde 会忽略不认识的字段，所以“只显示某一块”不能只加一个字段，否则旧版本会把它当成整个工作台显示。改为给这类小组件一个旧版本不认识的 `form` 值，和音乐小组件的 `MUSIC_FORM` 同样处理，旧版本就跳过它。合并进别的小组件的这类部分同样处理。
3. **单块小组件记住自己是哪一块**：小组件里存下模块名，或者贴的是哪一条便签。之后从边缘上拿掉这一块，不影响已经拖出的小组件。
   - 整个面板拖出的小组件跟着工作台的设置变化。
   - 按中转站的任何一个标签拖出，出来的都是整个中转站一块，带着三个标签。
4. **拖放要分去处**：现在 `catch` 接到的东西一律放进中转站。之后加上快捷 App（添加程序）和便签（附件）两个去处，按落点的区域区分。
5. **便签文件在外面被删**：确认是删除（不是编辑器用临时文件替换或改名）后，取消待写入的保存。没有未保存改动的便签直接关掉。有未保存改动的，留成一份可以恢复的草稿，不会被自动保存悄悄重建出文件。
6. **旁边展开的那一页放在哪里**：以那个面板或小组件所在屏幕的工作区为准，避开任务栏。两边都放不下时盖在它上面。移动、换屏幕、改缩放比例、拔掉显示器时重新计算。面板、这一页、它弹出的菜单和输入法的候选框算作一个整体，点它们之间的任何一处都不会让这一页收起。
7. **快捷 App 的身份**：“开始”菜单里的程序是外壳对象，不一定有 exe 路径。
   - 记下它的外壳解析名或商店应用的 AppUserModelID，启动时调用外壳对象的默认操作，商店应用按它自己的方式激活。
   - 拖进来的快捷方式保留快捷方式本身，不换成 exe。
   - 没有所在位置的（商店应用）不显示“打开文件所在的位置”。
   - 列举程序和取图标在 STA 后台线程做，不占面板线程。
8. **`Zone.Identifier` 不一定写了网站**：可能只有 `ZoneId`，也可能根本没有这个流。只在有可用的 `HostUrl` 或 `ReferrerUrl` 时写“来自某网站”，否则写所在文件夹。

### 实现情况（2026-10-18）

已在 feature/station 上实现，并在虚拟机里逐项验证过的，在提交说明里写明了。实现时定下的几处做法：

1. **快捷 App 是工作台的一个模块**（`apps`），和时间、中转站、便签一样有自己的开关和顺序。在边缘面板里它画成贴屏幕边缘的竖栏（顶部边缘时是三块下面的一行），竖栏底部放握把、固定和设置，面板底部那一栏就不要了。在小组件里它画成带名字的图标网格，小的时候是一排图标。
2. **单独拖出的一块**用一个旧版本不认识的 `form` 保存（`only:<模块>|<形式>`），旧版本会跳过这个小组件。
3. **旁边展开的那一页**是一个独立线程上的窗口（单线程套间，带 OLE），自己有消息循环。添加程序、编辑便签、预览中转站里的东西都在这一页上。它打开时面板保持展开，它收起后面板照常收起。
4. **便签的编辑**用 RichEdit 的无窗口文本服务（`ITextServices2`），由 Glance 实现宿主接口，文字用 `TxDrawD2D` 画进 Glance 自己画的页面里，光标由 Glance 按文本服务给的位置画。Markdown 的显示效果通过文本对象模型（TOM）套上去，套格式时暂停撤销记录，所以撤销只撤销打字。
5. **贴在桌面上的便签**是一个只显示这一条便签卡片的小组件。在卡片上点一下，在它旁边打开编辑页。在别处（面板里）再点这条便签，桌面上那张会被提到最前，面板收起，不会打开第二个编辑框。直接在桌面卡片上打字需要小组件的窗口能接收键盘和输入法，这一点放在小组件外壳的“编辑模式”里另做。
6. **拼音搜索**用 Unicode 官方的 Unihan 读音数据生成的首字母表（`scripts/pinyin.py`），一个字的所有读音都算，所以“网易云音乐”用 wyyyy 和 wyyyl 都能搜到。Windows 自带的中文读音转换接口在当前系统上已经不提供（返回“尚未实现”）。
7. **最近文件**以用户权限读变更日志，再按文件编号打开文件取路径。为了不把开发工具和程序产生的文件列进来，代码仓库（有 `.git`）和放着程序或库的文件夹里的文件都不列出。

## 九、便签编辑器升级（2026-10-21，主人确认）

目标：便签写起来像 Typora、Notion 这样的编辑器，文件里仍然是标准 Markdown。改动分两层：`notes::markdown` 负责“怎么读”（纯函数，全部有单元测试），`ui::note::Writing` 负责“按键和指针做什么”（同样把决定写成纯函数，测试不需要窗口）。两种画法（编辑时的 RichEdit 和没在编辑时的 `Frame::markdown`）必须一致，现有的逐像素对比测试继续保留并覆盖新内容。

### 1. 按标记显示原文（代替按行）

- 现在：光标或选区所在的整行显示原文，其他行收起标记。
- 改为：每个被收起的标记属于一个“结构”，记下这个结构的范围（UTF-16 单位）。
  - 粗体、斜体、删除线、链接、行内代码：结构是整个 `**…**`、`[…](…)`、`` `…` ``。
  - 标题：结构是整行（`#` 和文字）。
  - 待办：结构是 `- [ ]` 加后面那个空格（方框占的位置），按半开区间 `[开始, 结束)` 算，光标在文字开头（空格之后）不算碰到。
  - 表格：结构是整张表（见第 4 条），表里各格的行内标记也一起显示原文。分隔线：结构是那一行。
- 规则：光标（选区为空）落在结构范围里（行内标记和标题按闭区间 `[开始, 结束]`，待办按上面的半开区间），或选区和结构范围有重叠，这个结构的标记就显示原文，其他照常收起。
- `Shown` 里的 `line` 换成 `span`，`hidden`、`boxes`、`link_at` 改为按“正在编辑的位置”过滤。没在编辑（刚打开、没动过）时和现在一样全部收起。
- 收起的文字里也可能停着光标（点击、程序设置选区、撤销都可能把它放进去），不能假设 RichEdit 会跳过。所以每次选区变化后先按新位置决定显示哪些原文、重新排版，再把选区原样设回去，光标在收起文字里时，它所在的结构自然就显示出来了。

### 2. 列表

列表的结构一律按解析结果（pulldown-cmark，和显示用同一组选项 `markdown::READ`）来认，不用逐行的正则：代码块里的 `- ` 不是列表，`1.` 和 `1)` 是两个不同的列表，引用里的列表、同一行上嵌套的 `- - a`、懒惰续行（没有缩进的续行仍属于上一项）都按 CommonMark 的读法处理。这些决定都是 `notes::edit` 里的纯函数，输入是全文和光标或选区（UTF-16 单位），输出是一次替换加替换后的选区，全部有单元测试。

- **回车续行**：光标所在行有列表项的标记、光标在标记（和待办方框）之后时，回车插入换行和同样的前缀：
  - 无序：同样的符号。有序：编号加一，保持 `.` 或 `)`。待办：新行总是 `[ ]`。
  - 前缀里引用的 `>` 照抄，同一行上外层项的标记换成等宽的空格，所以新项和原来那一项对齐。
  - 光标后面的文字和原来那一项下面的内容（子列表、续行）都归新项，跟着新项文字的起始列移动（编号从 9 变成 10 时多缩进一格）。
  - 光标在标记之前、在续行上、在代码块里时，按普通回车处理。
  - 空的列表项（标记后面没有文字，下面也没有内容）按回车：嵌套的项先减一级缩进。不嵌套的项，是列表最后一项时这一行留空，光标放到再下一行（中间隔一个空行，之后写的字就不再属于列表），不是最后一项时去掉标记，后面的项重新编号。
- **Tab / Shift+Tab**：从选区第一行开头的那个列表项起，选中的同级各项连同下面的内容一起移动。Tab 移到前一个同级项下面，起始列对齐它的文字（`- ` 下是 2，`1. ` 下是 3）。Shift+Tab 移到所在父项的起始列。没有前一项（或没有父项）时什么也不改，按键也不做别的。第一行不是列表项时 Tab 照旧插入制表符。
- **退格**：光标正好在列表项文字开头（标记和方框之后）且没有选区时：
  - 嵌套的项先减一级缩进。
  - 否则去掉标记（待办连同方框）：前面有同级项时，这一行变成前一项里的一段，缩进到前一项文字的起始列（和 Word、Google 文档一样，文字位置不跳）。是列表第一项时，这一行变成列表前面的一段。
  - 后面的有序项接着原来的起始编号重排。原来的起始编号不是 1 时，中间补一个空行，因为紧跟在段落下面的有序列表只能从 1 开始（否则会被读成段落的续行）。
- **有序列表重排**：列表动作改到的有序列表，从它第一项原来所在列表的起始编号起依次重写编号，新加的项按写下的编号算。编号宽度变化时，这一项下面的内容跟着移动，保持在这一项里。重排时把这些列表项先按“编号为 1、位数不变”来解析，避免移动中的项因为编号不是 1 而被读成段落续行。编号最多九位，再大就不续了。只有列表动作（回车、退格、Tab、Alt+↑↓）会重排，加粗、标题、勾选待办不会动编号。撤销和重做不触发重排。
- **Alt+↑ / Alt+↓**：选中的各行（选区结束在某行行首时那一行不算）和上一行或下一行交换，选区跟着移动，涉及的有序列表随后重排，起始编号保持不变。

### 2.1 按键怎么接进来

- 拦截放在 `WM_CHAR` 而不是 `WM_KEYDOWN`：消息循环里 `TranslateMessage` 已经为回车、Tab、退格生成了字符消息（`'\r'`、`'\t'`、`'\b'`），只拦 `WM_KEYDOWN` 时字符还会再到一次。Ctrl 组合键（Ctrl+B 等）也以控制字符的形式到 `WM_CHAR`，同样在这里拦，`WM_KEYDOWN` 里只处理没有字符的键。
- Alt+↑ / Alt+↓ 来的是 `WM_SYSKEYDOWN`，`Writing::answer` 要接这个消息，处理了就不再交给系统（否则会激活窗口菜单）。
- 输入法组字时（`ITextServices` 报告正在组字，或收到 `WM_IME_STARTCOMPOSITION` 之后、`WM_IME_ENDCOMPOSITION` 之前）所有动作都不拦截，点方框勾选也不做。
- 每个动作用一次 `ITextDocument::BeginEditCollection` / `EndEditCollection` 包起来：写入替换、设好选区，撤销一次撤回整个动作（包括重排的编号）。打字触发的重排（例如在有序列表中间粘贴了一项）也和那次输入合成一步。

### 3. 待办

- 编辑时也能点方框勾选：方框只要画着（光标没碰到它）就能点。点方框不移动光标。
- **Ctrl+Enter**：当前行是待办则切换勾选（只改方框里那个字符）。是普通列表项则在标记后加 `[ ] `。不是列表则在文字开头（引用的 `>` 和缩进之后）加 `- [ ] `。在代码块里不做。
- 注意 `- [ ]` 后面没有文字时，解析器不把它当成待办（不画方框），但编辑动作照样按方框处理，这样回车续出来的空待办行按回车能正常结束。

### 4. 表格（GFM）

- 解析打开 `ENABLE_TABLES`（加进 `markdown::READ`，显示和编辑动作同时生效）。
- 没在编辑这张表时，表格不用 RichEdit 的文字来画，而是由一个两种画法共用的表格排版（`notes::table`，DirectWrite）来画：
  - 它从解析结果读出各行各格（注意：pulldown 不给分隔行事件，要从原文找。单元格范围包含两边的空格，要去掉。缺的格是零长度。对齐方式 `:---:` 读自分隔行），量出每格文字的宽度，列宽 = 这一列最宽的格加左右留白，表头加粗，画外框、表头下的线和格间细线。一行放不下时格内文字换行，行高随之增加。
  - 编辑器里这张表的原文整个收起，RichEdit 只为它留出和排版结果一样高的空白（用表格第一行的段前间距撑开），表格由 `Writing` 在这块空白上画。`Frame::markdown` 在同样的位置画同一个排版结果，所以两种画法逐像素一致，现有的对比测试加上表格和分隔线。
  - 点击表格里的某一格：从排版结果找到这一格在原文里的位置，光标放进去，整张表随即显示原文。
- 光标碰到表格时整张表显示原文（竖线和分隔行都显示），不做对齐。
- 表格里 Tab 跳到下一格（选中那一格的文字），Shift+Tab 跳到上一格。最后一格按 Tab 在下面加一行同样列数的空行。表格里回车照常换行。表格最后一行下面必须有空行才能接正文（否则下一行会被读成表格的新一行），所以插入表格时总在后面带一个空行。
- `标题\n---` 是二级标题（setext），不是“段落加分隔线”，插入分隔线时前面补空行。

### 5. 分隔线

- 单独一行的 `---`、`***`、`___`（CommonMark 的 thematic break）：没在编辑这一行时，文字收起，在这一行中间画一条贯穿整个文字区域的淡线。

### 6. 格式

- **选中文字时的格式条**：选区不为空且不在组字时，在选区上方（放不下就在下方）显示一条小工具栏：粗体、斜体、删除线、行内代码、链接。由 `Writing` 自己画（位置和大小按便签的缩放和屏幕缩放换算），所以面板旁边的编辑页和桌面上的便签都一样。鼠标拖选过程中不显示，松开后出现。点格式条不改变选区。
  - 点击要先经过 `Writing` 的命中测试，再交给编辑器或宿主：桌面便签的 `write`（按下即开始编辑）和旁边编辑页的 `WM_NCHITTEST` 返回 `HTCAPTION`（拖动窗口）都会先吃掉按下，所以两个宿主都先问 `Writing` 这一点是不是格式条，是就交给它。
- **切换规则**（粗体为例，斜体、删除线、代码相同）：
  - 选区完全在一个粗体结构的文字里（或正好是整个结构）：去掉这个结构的两端标记。
  - 否则：去掉选区两端的空白后，在两端加上 `**`。跨多行时逐行处理，空行和代码块里的行跳过，列表的标记、待办方框、标题的 `#`、引用的 `>` 不包进去（从这一行文字开头算起）。
  - 行内代码用比文字里最长的一串反引号还多一个的反引号包起来，文字以反引号开头或结尾时里面加一个空格（CommonMark 读的时候会去掉）。去掉代码标记时同样去掉这两个空格。
  - 处理后选区仍然选着原来的文字。
- **快捷键**：Ctrl+B 粗体，Ctrl+I 斜体，Ctrl+Shift+X 删除线，Ctrl+E 行内代码，Ctrl+K 链接，Ctrl+1/2/3 设为一到三级标题，Ctrl+0 设为正文（去掉 `#`）。下划线式标题（setext）设标题时改写成 `#` 的写法并去掉下面那一行，Ctrl+0 也去掉那一行。代码块里的行不改。
- **链接**：有选区时变成 `[选中文字]()`，光标放进括号里。剪贴板里正好是一个网址时直接填进去，光标放在链接后面。没有选区时插入 `[]()`，光标放进方括号。选区跨行时不做。文字里不成对的方括号加反斜杠转义。地址里有空格、尖括号、反斜杠或不成对的圆括号时用 `<…>` 包起来（里面的尖括号和反斜杠再转义）。

### 7. 右键菜单

在便签文字上右键弹出菜单（用 `ui::menu`，和其他菜单一样的样子）：剪切、复制、粘贴，分隔，插入待办、插入表格（两列两行）、插入分隔线、插入代码块、插入链接，分隔，一级标题、二级标题、三级标题、正文。插入的内容放在光标处，块级内容（表格、分隔线、代码块）前后补空行，使它单独成块。

- 菜单由 `Writing` 决定内容和执行，宿主只负责在哪里弹出：桌面便签的右键抬起现在被 `panel.rs` 的组件菜单接走（约 1151 行），正在编辑便签时改为先交给 `Writing`。旁边编辑页已有自己的菜单（线程局部的 `MENU`），便签文字上的右键用同一个非模态菜单，不嵌套第二个消息循环，菜单开着时再次右键先关掉旧的。
- 键盘的菜单键和 Shift+F10 给的位置是 (-1, -1)，这时菜单弹在光标所在位置下方。

### 8. 粘贴

- 选区不为空、剪贴板是一个网址（只有一行，`http://` 或 `https://` 开头，没有空格）时，选中的文字变成 `[文字](网址)`。
- 剪贴板有 HTML（`HTML Format`，网页和 Word 都会放）时，把它转成 Markdown 再粘贴：标题、粗体、斜体、删除线、链接、行内代码、代码块、列表（含嵌套和待办）、引用、表格、段落和换行。不认识的标签只保留文字。图片转成链接文字。
- 转换用一个只做这件事的模块 `notes::html`：
  - `HTML Format` 的头部给的 `StartFragment`/`EndFragment` 是从整段数据开头算的 UTF-8 字节偏移，按字节切出片段，再按 UTF-8 解码。
  - 用 html5ever（加进依赖）把片段解析成树，按元素走一遍。样式要沿树继承（`<span style="font-weight:bold">` 这类，Word 和很多网页不用 `<b>`），用一个样式栈记录当前粗、斜、删除线、等宽。
  - Word 的列表不是 `<ul>`/`<ol>`，而是带 `mso-list` 样式的段落，层级在样式里（`level2` 等），编号或符号写在 `<![if !supportLists]>` 包着的文字里。按这些还原成 Markdown 列表，去掉 Word 自己写的符号。
  - 转出的文字里 Markdown 的特殊字符要转义，避免原文里的 `*`、`#` 被读成格式。
  - 单元测试覆盖网页（浏览器复制）和 Word 两种常见片段。
- 粘贴必须自己接管：编辑器开着 `TXTBIT_RICHTEXT`，交给 RichEdit 粘贴会把字体颜色等富文本带进来。所以 Ctrl+V、Shift+Insert、菜单里的粘贴都走同一条路：有 HTML 按上面转换，否则取 `CF_UNICODETEXT`，统一换行为 `\n`，用一次替换写入（和其他动作一样包成一步撤销）。

### 9. 不做的

- 自动补全括号和星号（中文输入时容易误触）。
- 第一期不在便签里显示图片，不做便签内查找（以后再做）。
